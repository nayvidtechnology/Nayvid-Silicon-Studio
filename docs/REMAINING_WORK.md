# Remaining Work

## 1. Dynamic UI Visualizations
The visual renderers in `apps/renderer/src/ui/desktop-ui.ts` for Waveform and FSM are currently mock stubs.
- **Waveform Viewer**: Must iterate through `WaveformModel.signals` to genuinely render timing/transitions instead of returning a flat straight line SVG for each signal.
- **FSM Viewer**: Must traverse the states and transitions within `DesignFSM` (generated by the backend) and properly draw interconnected nodes rather than a hardcoded `<circle>` and "FSM Active" text.
- Both components need to bind to the actual JSON schema fields returned by the Universal Tool Bus.

## 2. Safe Electron Backend Architecture
Currently, the Electron main process (`apps/desktop-electron/src/main.ts`) dynamically requires `StudioProductionController` from the renderer's built asset directory (`../../renderer/dist/production.js`).
- **Architectural risk**: This is an unsafe paradigm and leads to runtime crashes (`MODULE_NOT_FOUND`) when packaged.
- **Solution**: Relocate `StudioProductionController` and its associated interfaces from `apps/renderer/src/production.ts` into a shared backend module (e.g., `packages/platform-core` or `packages/engineering-core`).
- **Static Import**: The desktop process should then statically `import { StudioProductionController } from '@nayvid/platform-core'` to instantiate it safely.
